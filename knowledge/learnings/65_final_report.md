# Final reports to a funder

Additional rules for the report that closes a funded project, on top of the general writing conventions, which apply here as well. Funder-specific formatting is a local matter and belongs in the report's own `CLAUDE.md`, as for proposals ([60_grant_proposal.md](60_grant_proposal.md)).

## Achieved against proposed, deviations framed by what was gained

Most report forms ask for the deviations from the proposal, so none is left out. The paragraph opens with what was done or gained instead, then gives the factual reason. Two patterns: "Automatic focus finding was not needed, because cutting under liquid nitrogen produced flat surfaces"; "The project used the time planned for X for Y, which had to precede Z." A main objective that was not reached is stated as the prerequisite now in place, the obstacle that remains, and the next step, not as a list of what is missing.

The limit: write "not needed" only if it was factually not needed. If time ran out, write "was not carried out" and say what the time went into. Positive framing changes the weighting, not the finding; a reviewer who checks the claim against the publications must find it true.

## Every result section points to its own publication

Each subsection or work package ends with a sentence such as "Details can be found in our publication [n]." Report forms usually allow published work to be summarised briefly and referenced. The reviewer then sees without searching that, and where, the result is published, and the report stays short. Content-bound citations inside the paragraph are unaffected.

## AI-assistance declaration

As for proposals: the share of model assistance is a statement by the applicant, never an estimate derived from the `Laborbuch.md`. Ask the user for the wording, and check the current report form for what the funder requires.
