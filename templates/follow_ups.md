# Follow-ups

Research ideas that left their project, because that project will not pursue them (the paper is full, the project is finished). Copied to the workspace root as `Follow-ups.md` on the first entry; until then the file need not exist.

**Boundary.** "Parked" in a project's `Todo.md` means the project comes back to it. An entry here means a future project has to pick it up. An entry lives in one place only: when it moves here, it is deleted from the project, with a dated line in that project's lab book. An archived project is not edited; its entry is copied.

**When to write.** At the moment of the decision, from inside the project. "Later, but not in this project" goes here; "later, here" goes to "Parked"; a bare "for later" gets one question.

**Self-contained entries.** When the entry is read again, the old project is not loaded. Each entry therefore names the idea, the occasion (the finding, with its number), the approach, the sources (lab-book date, runs, scripts) and the date and reason it moved here. Paths are relative to the originating project; its folder goes into the section heading when it differs from the project name.

**Taking over.** A successor project created with `/new-subproject` presents the entries of its declared predecessors one at a time, and the user decides each → `knowledge/learnings/50_new_subproject.md`, step 4.
